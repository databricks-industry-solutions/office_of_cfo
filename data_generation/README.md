# Milestone 1 — Synthetic close data

Vertical-neutral, deterministic (`seed=42`) synthetic data for the month-end close,
landed in Unity Catalog under the baseline_raw schema (configurable via CFO_CATALOG).

## What it produces

**ERP feeds** (parquet → `output/landing/` → raw Delta tables):

| Table | Grain | Notes |
|---|---|---|
| `dim_org` | business unit | org hierarchy: region → country → legal entity → BU (+ primary source system; NL runs AFAS) |
| `chart_of_accounts` | account | vertical-neutral accounts (+ `account_group` for the rollup tree); control accounts flagged + mapped to subledgers |
| `gl_journal_entries` | JE line | balanced journal entries (+ `business_line` tag, named `source_system`), except a seeded batch |
| `subledger_ap` | invoice | vendor invoices (SAP/AFAS) → AP control (20000) |
| `subledger_ar` | invoice | customer invoices (SAP/AFAS) → AR control (11000) |
| `subledger_payroll` | payroll run | Workday → Payroll Liabilities control (22000) |
| `subledger_fixed_assets` | asset | gross cost + monthly depreciation |
| `subledger_inventory` | item | SAP on-hand value + product costs → Inventory control (12000); drives DIO |
| `subledger_sales_orders` | order | SAP order-to-cash upstream of AR |
| `subledger_procurement` | PO | SAP procure-to-pay upstream of AP (3-way matched) |
| `subledger_bank` | statement | Bank Feed closing balances → cash control (10100) |
| `subledger_staff_expenses` | claim | Workday employee T&E |
| `budget_forecast` | account × BU | IS forecast for the close period (OpEx seeded to run *over* forecast) |
| `kpi_history` | scope × month | trailing DSO/DPO/DIO/CCC snapshots per scope (direction of travel) |

**Close-folder spreadsheets** (CSV → `output/close_folder/` → UC Volume `close_folder`):
`accruals`, `reclasses`, `intercompany`, `fx_overlays` — the simulated SharePoint
"Month-End Close" folder. Ingested with schema evolution by the Milestone 2 pipeline.

## Seeded issues (the demo's spine)

| Issue | Type | Where it surfaces |
|---|---|---|
| AP invoices in subledger but delayed in GL (BU-300) | reconciliation timing break | Act 4 — residual aged recon items |
| Legacy-ERP batch off by $1,250 | DQ validity (debits = credits) | Act 2 — DQ failure |
| AP invoice referencing account `99999` | DQ referential integrity | Act 2 — DQ failure |
| Fixed-assets feed (`SAP-FixedAssets`) `load_ts` 3 days stale | DQ freshness | Act 2 — DQ failure |
| `accruals` CSV column `amount` → `adjustment_amount` | schema evolution | Act 2 — schema evolution + ZeroOps self-heal |
| BU-100 inventory relief (COGS) missing from GL | reconciliation (Inventory) | Act 4 — Inventory control break |
| BU-400 bank deposit in transit | reconciliation (Bank) | Act 4 — Bank control break |
| PO amount ≠ matched invoice | DQ three-way match | Act 2 — procurement DQ failure |

`output/landing/seeded_issues_manifest.json` is the machine-readable list (drives the
DQ + ZeroOps narrative downstream).

## Run

```bash
# 1. Generate local files (no Databricks needed)
uv run --with pandas --with numpy --with pyarrow --with pyyaml \
  python generate_close_data.py

# 2. Upload to volumes + build raw UC tables
# Set DATABRICKS_CONFIG_PROFILE (or DATABRICKS_PROFILE) and DATABRICKS_WAREHOUSE_ID
uv run --with databricks-sdk --with pyyaml python load_to_uc.py
```

Targets are read from `../config/demo.yaml`. `output/` is regenerated by every setup run; only `output/landing/` is committed (the seed-invariant tests read it).
